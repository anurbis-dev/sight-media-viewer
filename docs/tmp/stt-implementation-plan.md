# План реализации гибридного модуля распознавания речи (STT) для десктопного приложения

## 1. Цель и ограничения проекта
- **Задача:** Реализовать лёгкий, бесплатный и отказоустойчивый модуль распознавания речи (Speech-to-Text) на русском языке (`ru-RU`) для кроссплатформенного десктопного приложения (Windows / macOS).
- **Жёсткие ограничения:**
  - Запрещено встраивать локальные ML-модели (Whisper weights и аналоги) в дистрибутив — вес приложения не должен увеличиваться.
  - Использовать только бесплатные API и встроенные системные фреймворки ОС.
  - Обеспечить бесшовный фолбэк (резервирование) при сетевых сбоях, региональных блокировках или исчерпании бесплатных лимитов.

---

## 2. Архитектура решения (3-уровневый пайплайн)

Модуль строится по паттерну **Strategy + Fallback Router**:

1. **Уровень 1 — Основной облачный провайдер (Кроссплатформенный):**
   - **Сервис:** Groq Cloud API (`https://api.groq.com/openai/v1/audio/transcriptions`)
   - **Модель:** `whisper-large-v3-turbo`
   - **Параметры:** `language="ru"`, `response_format="json"`, `temperature=0.0`
   - **Условия переключения на резерв:** таймаут ответа (> 4 сек), HTTP-ошибки `429` (Rate Limit), `5xx`, сетевая недоступность или отсутствие API-ключа.
2. **Уровень 2 — Системный резерв для Windows:**
   - **Движок:** Нативный Windows Speech API (`Windows.Media.SpeechRecognition.SpeechRecognizer` или `System.Speech.Recognition`).
   - **Локаль:** `ru-RU`.
   - **Особенности:** Нулевой вес, работает без API-ключей, не имеет жёстких лимитов на длительность сессии.
3. **Уровень 3 — Системный резерв для macOS:**
   - **Движок:** Нативный фреймворк Apple Speech (`SFSpeechRecognizer`).
   - **Локаль:** `Locale(identifier: "ru-RU")`.
   - **Особенности:** Нулевой вес, высокая точность пунктуации. Требует программного перезапуска сессии каждые 50–55 секунд (системный лимит Apple — 60 секунд на одну непрерывную сессию).

---

## 3. Пошаговый план разработки для AI-агента

### Шаг 1: Проектирование единого интерфейса (`ISTTProvider`)
- Создать абстрактный интерфейс / базовый класс провайдера распознавания речи со следующими методами и событиями:
  - `startRecording()` / `stopRecording()`
  - `transcribeAudio(audioBuffer, format) -> Promise<TranscriptionResult>`
  - События/коллбэки: `onPartialResult(text)`, `onFinalResult(text)`, `onError(error)`, `onProviderChanged(providerName)`.
- Определить структуру результата `TranscriptionResult`: `{ text: string, provider: 'groq' | 'windows_native' | 'macos_native', durationMs: number, isFallback: boolean }`.

### Шаг 2: Реализация модуля захвата и подготовки аудио
- Настроить запись звука с микрофона в кроссплатформенном формате:
  - Частота дискретизации: `16000 Hz` (оптимально для Whisper и системных движков).
  - Каналы: `1` (Mono).
  - Формат буфера для Groq: сжатый `.ogg` (Opus) или `.m4a` / `.wav` (PCM 16-bit) для минимизации размера пакета и ускорения отправки по сети.
- Добавить базовый VAD (Voice Activity Detection) или проверку уровня громкости, чтобы не отправлять тишину в API и экономить бесплатные лимиты Groq.

### Шаг 3: Интеграция основного движка — Groq API (`GroqSTTProvider`)
- Реализовать HTTP `multipart/form-data` клиент к эндпоинту `/openai/v1/audio/transcriptions`.
- Передавать поля: `file`, `model: "whisper-large-v3-turbo"`, `language: "ru"`.
- Добавить поддержку опционального HTTP/SOCKS5-прокси в настройках клиента (актуально для пользователей из РФ).
- Настроить строгий таймаут подключения и ответа (например, `4000 мс`) и обработку статуса `429 Too Many Requests` с немедленным выбросом исключения `FallbackRequiredError`.

### Шаг 4: Интеграция системного резерва Windows (`WindowsNativeSTTProvider`)
- Реализовать нативный бридж/модуль для Windows 10/11:
  - Инициализировать `SpeechRecognizer` с языковым тегом `ru-RU`.
  - Включить диктовку (`SpeechRecognitionTopicConstraint` с темой `Dictation`).
  - Реализовать обработку ошибок отсутствия установленного языкового пакета распознавания речи в Windows (выводить понятную подсказку пользователю при необходимости).

### Шаг 5: Интеграция системного резерва macOS (`MacOSNativeSTTProvider`)
- Реализовать нативный Swift/Objective-C модуль или FFI-бридж с использованием `Speech` и `AVFoundation`:
  - Инициализировать `SFSpeechRecognizer(locale: Locale(identifier: "ru-RU"))`.
  - Реализовать запрос разрешений у пользователя (`SFSpeechRecognizer.requestAuthorization` и `AVCaptureDevice.requestAccess(for: .audio)`).
  - Добавить в конфигурацию сборки macOS (`Info.plist`) обязательные ключи:
    - `NSSpeechRecognitionUsageDescription`
    - `NSMicrophoneUsageDescription`
  - Реализовать таймер автоперезапуска задачи (`SFSpeechAudioBufferRecognitionRequest`) на 55-й секунде, склеивая распознанный текст без потери слов на стыке.

### Шаг 6: Реализация оркестратора и логики фолбэка (`STTRouter`)
- Объединить провайдеры в единый менеджер:
  - По умолчанию активен `GroqSTTProvider`.
  - При получении `FallbackRequiredError` (нет сети, таймаут, лимит `429`, невалидный ключ) автоматически переключать текущий запрос на `WindowsNativeSTTProvider` или `MacOSNativeSTTProvider` в зависимости от `process.platform` / ОС.
  - Добавить механизм *Circuit Breaker*: если Groq недоступен 3 раза подряд, временно (на 5–10 минут) использовать сразу системный движок ОС без задержки на ожидание таймаута Groq, после чего делать пробный запрос.
  - Для режима непрерывной диктовки предусмотреть параллельную буферизацию аудио: пока аудио пишется для отправки в Groq, нативный движок ОС может отдавать мгновенный черновой текст (`onPartialResult`), который затем заменяется точным текстом от `whisper-large-v3-turbo`.

### Шаг 7: Настройки UI и хранение ключей
- Добавить в настройки приложения:
  - Поле ввода `Groq API Key` (хранить безопасно в системном Keychain / Windows Credential Manager).
  - Переключатель режима работы: `Авто (Groq + Резерв ОС)` / `Только системный движок ОС`.
  - Поле опционального прокси-сервера для запросов к Groq.
  - Индикатор в интерфейсе, показывающий, какой движок обработал последнюю фразу (например, иконка облака для Groq или щита/ОС для локального системного API).

---

## 4. Критерии приёмки (Definition of Done)
1. Размер установщика приложения увеличился менее чем на **2 МБ** (отсутствуют внешние веса нейросетей).
2. При наличии валидного ключа Groq и интернета русская речь распознаётся через `whisper-large-v3-turbo` с корректной пунктуацией.
3. При отключении интернета, блокировке API или удалении ключа Groq приложение без зависаний и ошибок автоматически переключается на `Windows Speech` (на Windows) или `Apple Speech` (на macOS).
4. На macOS корректно запрашиваются системные разрешения микрофона и распознавания речи без падения приложения (`SIGABRT`).
5. Длительная диктовка на macOS (> 60 секунд) через системный движок не обрывается.
