## 0.8.0 — 2026-09-24 — Scan ignore list; compiled .obj files skipped; 3D textured mode no longer freezes on multi-material meshes
- **What:** Settings → Scanning → Ignore: one pattern per line (`*.meta`, `Library/`, `BurstCache/`, `Library/PackageCache`, `# comment`), *Apply* hides matching files and folders in every source and rescans. `.obj` files that are compiler output (MSVC/COFF — Unity BurstCache, VS `obj/`) are no longer indexed as 3D models; ones indexed earlier disappear on the next scan. Fix: the 3D lightbox froze (render loop threw every frame) in Textured mode on FBX files with a multi-material mesh.
- **Where:** `library.py`: `IgnoreRules`, `rel_parts`, `Library.ignore` (loaded in `__init__` from the new `meta` table, key `scan_ignore`), `hidden()`, `set_ignore()`, `scan_source` (dir pruning + `hide` list), `set_excluded` (re-including a folder does not revive ignored files), `_touch_one` (watcher). `fileinfo.py`: `obj_is_binary` (shared by scanner and info overlay). `server.py`: `PUT /api/scan/ignore`, `/api/state` → `scanIgnore`. `index.html`: Settings "Scanning" block (`#scanIgnore`, `applyScanIgnore`, `refreshMeta` fills the textarea unless it has unsaved edits), `applyXray` / new `xrayMaterial`.
- **Notes:**
  - Ignored files reuse `status='excluded'` (same as an excluded folder), so tags/ratings/notes survive and every query that already skips excluded rows works unchanged. Consequence: revival must check both — `set_ignore` revives an excluded row only if it is in no excluded folder and not `hidden()`; `set_excluded` skips `hidden()` rows when re-including. Anything new that flips rows back to 'ready' must do the same.
  - Patterns are relative to the source root (the root folder's own name never matches) and case-insensitive; no `!` negation. The list is global, not per source. It lives in the library DB, not settings.json, because the scanner needs it at startup before any page is open.
  - Freeze cause: `c.material` is an array for multi-material meshes; Textured mode restores that array from `origMats`, and `applyXray` (run after every base-mode switch to reapply x-ray) read `m.userData` of the array. Other shading modes replace the array with one material, so only Textured broke. Anything else that walks `c.material` must handle arrays.
  - Tested: API round trip on an isolated `SIGHT_HOME` (ignore, clear → restored, a pre-existing 'ready' COFF row hidden by rescan, watcher skips new ignored/COFF files), Settings UI with Playwright, and the reported Unity crate FBX: solid → x-ray → textured → x-ray with no page errors.

## 0.7.0 — 2026-09-24 — UV pane toolbar: UV set and texture channel; static highlight; UV button on the left
- **What:** the UV pane has a bottom toolbar (the 3D shading bar's look): UV1/UV2/… buttons when the shown meshes carry more than one UV set, and a channel list (RGB, RGBA over a checker, R, G, B, A as grayscale) when a texture is under the UVs. The polygon highlight no longer pulses (static orange). The *UV* button moved to the left end of the 3D toolbar (the pane opens on the left), and with the split on that toolbar centres on the model's half.
- **Where:** `index.html`: `refreshUv` (builds `.uv-bar`, `uvChan` / `sight.uvChan`, `UV_CHANNELS`), `makeModelInspector` → `renderUV(sel, chan)` (`uvCount`, `uvGeometry`, `bgShader`, returns `sets/set/hasBg`), `ins.uvSet` (per model, not persisted), `select()` (no `onBeforeRender`), `#v3dShade` markup and `#v3dShade { left: … var(--uv-left) }`; `.opt select` rule shared with `.uv-bar select`.
- **Notes:** UV sets are `uv`, `uv1`, `uv2`, `uv3` (three's names for TEXCOORD_0..3). The chosen set is fed to the UV shader through a per-(mesh, set) proxy `BufferGeometry` that shares the mesh's attribute objects as `position` + `uvSel`; these proxies are cached and deliberately never disposed — `geometry.dispose()` frees the GL buffers of shared attributes, which the model still renders with. Channels: sRGB textures sample as linear and the readback re-encodes, so R/G/B show stored values; alpha is pre-decoded in the shader so it survives the encode. Normal/ORM maps (non-sRGB) are shown raw. Meshes lacking the chosen set are skipped. Tested with Playwright on an isolated `SIGHT_HOME` with a generated GLB (TEXCOORD_0 + TEXCOORD_1, RGBA PNG): set switching, A/RGBA/R views, toolbar order, no console errors. No library model has a second UV set, so real-world multi-set files were not tried.

## 0.5.0 — 2026-09-24 — Info overlay: button top-left, richer video, 3D materials/textures with highlight
- **What:** the *i* button moved from the lightbox bar to a round button in the stage's top-left corner; the panel opens beside it. Video: duration now shows the exact frame count, plus color profile (Rec. 709 / Rec. 2020 / Rec. 601 / P3, transfer PQ/HLG), color range, SDR/HDR, chroma subsampling, scan, start timecode; key fields (duration, fps, size, codec) come first. 3D meshes: "Materials" (rendered shaded balls, name, triangles, texture count) and "Textures" (thumbnail, name, resolution, slots such as "Roughness, Metalness"); clicking one highlights its polygons in pulsing orange with a faint wireframe, clicking again clears it. A failed info request is shown ("restart Sight to load the new server code" on a 404) instead of silently showing nothing.
- **Where:** `fileinfo.py`: `_color_profile`, `_count_frames`, `_video_rows` (reordered), `_av`; `index.html`: `.info-fab` / `.li-*` CSS, `renderLightInfo` (errors, scroll kept, inspector sections), `onLightInfoClick`, new `makeModelInspector` (replaces `modelSceneInfo`), `v3dInspect` global next to `v3dCam`, set in `boot3d`, disposed in `dispose3d`.
- **Notes:**
  - Frame count: `ffmpeg -i f -map 0:v:0 -c copy -f null -` (remux, no decode — ~0.1 s for small files, disk speed for big ones), last `frame=` in stderr; skipped over 6 GB or after 15 s, then "≈ fps × duration" is shown. Color tags come from the pixel-format parens of the `ffmpeg -i` banner: "tv, bt709" = all three agree, otherwise "matrix/primaries/transfer".
  - Thumbnails are rendered by the viewer's own renderer into a 72² MSAA render target and read back, one per frame (a material in the ball scene's light setup compiles a new program). Render targets are linear with no tone mapping in three r185, so sRGB is encoded by hand with a LUT; non-sRGB textures (normal/ORM) are shown raw. glTF textures (`flipY=false`) are drawn on a Y-flipped quad. Materials with vertex colors are cloned without them for the ball. Up to 160 thumbnails.
  - Highlight overlays live in the **scene**, not in the model: `applyBaseMaterial` / x-ray / wireframe traverse the model and would restyle or crash on them. Each overlay shares the source geometry, overrides `updateMatrixWorld` to copy the source's world matrix (and `bindMatrixInverse` for skinned meshes, bound to the same skeleton), so explode and turns carry it along. Multi-material meshes: the other groups get an invisible material. Highlight color is fixed orange (the theme accent can be near-white).
  - Material/texture lists come from `origMats`, so the current shading mode (solid/normal) does not change them; the Scene counts use them too (the old code counted the swapped solid material).
  - Closing the overlay clears the highlight. Splats keep only the Scene counts. Tested with Playwright on an isolated `SIGHT_HOME` (18-material GLB, 1-material/3-texture GLB, H.264 mov).

## 0.3.0 — 2026-09-24 — 3D viewer: soft shadows with light size, environment shadow on the floor, floor fades on explode
- **What:** lightbox 3D shadows no longer show stair steps. Each light has a **Size (softness)** slider (angular diameter, 0–45°): 0 gives a crisp, anti-aliased edge; larger sizes give soft shadows that stay sharp where an object touches the floor and blur with distance (contact hardening). Ambient and Environment light now cast a soft shadow on the floor too (they fill direct shadows and darken the floor under/around the model), weighted by the sky's brightness per direction, so a custom env image with a bright spot throws its shadow away from it. With explode, the floor, grid and its shadows fade out smoothly once parts sink below the floor, and fade back when they return.
- **Where:** `index.html`: new `PCSS_GLSL` / `patchSoftShadows` / `pcssRadius`, `skyLumFromPreset` / `skyLumFromImage`, `makeSkyOcclusion` (next to `applyExplode`); `boot3d` rig: `fitShadows`, `onExplodeMoved`, `syncRig` (light size, floor fade, sky-shadow restart key, shadow-only mix), `fitRig` (floor/grid centred on the model, measured with explode undone); `v3dLightRows` (Size slider); `DEFAULT_V3D` + `defaults.json` (`l1size`/`l2size`/`l3size`, `shadowStrength` 0.35 → 0.6).
- **Notes:**
  - Shadows: renderer uses `BasicShadowMap` and `patchSoftShadows` swaps that mode's `getShadow()` in `THREE.ShaderChunk.shadowmap_pars_fragment` for PCSS (16 blocker taps + 32 filter taps, receiver-plane depth bias via `dFdx`). `light.shadow.radius` is repurposed: penumbra radius in shadow UV per unit shadow depth (`pcssRadius`). If a three.js update changes the chunk text, the patch logs a warning and falls back to `PCFShadowMap` (radius in texels) — re-check the markers after upgrading `vendor/three*`. The patch is global but only affects Basic-mode shadows; nothing else in the app uses them.
  - Shadow frusta now hug the model's bounding sphere (was ±diagonal, half the texels wasted) at 2048², refit on turn and on every explode change; lights are placed around the model centre, not the orbit target, so panning away never loses the shadow.
  - Sky shadow (`makeSkyOcclusion`): 64 cosine-distributed directions, 8 per frame, each a soft shadow map rendered onto a 512² floor texture and summed; camera-independent, restarts only when env on/off/preset/image, env strength, ambient, custom-image yaw, turn or explode change. **Gotcha:** three picks shadow casters by the *rendering* camera's layers, so each sample renders twice — an empty-frustum camera on layers 5+6 refreshes the sample light's map (the model is put on layer 6 by `markCasters`), then a layer-5 camera draws the receiver with `shadowMap.autoUpdate` off. The solid floor uses the result as `aoMap` (scales exactly its ambient + env light); the shadow-only floor gets an overlay plane. Shadow-only darkness is split by energy: direct shadows × direct share, sky shadow × ambient+env share (so turning env up lightens direct shadows, as on the solid floor).
  - Explode fade: target = 1 − smoothstep(depth of the lowest part below the floor / 15% of model size), eased over ~120 ms. The floor stays where the assembled model stands.
  - Not done: objects don't get env shadows on themselves (no SSAO); the thumbnail renderer is unchanged. The custom-image sky direction follows three's `envMapRotation` for PMREM maps (lookup = Ry(−yaw)·dir) — verified only for presets (symmetric), not with a real HDRI.
  - Tested with Playwright on an isolated `SIGHT_HOME` (multi-part OBJ): hard/soft/env/env-only/shadow-only/explode.
